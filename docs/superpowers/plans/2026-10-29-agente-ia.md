# Agente IA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add invoice-from-photo (Facturas tab) and an AI chat that answers and proposes confirmed changes (new Agente IA tab) to Ventas y facturación, using OpenRouter.

**Architecture:** A second migration lets invoices exist without a sale (`origen = 'foto'`, own number, chosen IVA, stored photo). Pure logic (client matching, amount prefill, invoice actions) lives in `src/lib/`. Two Next route handlers under `src/app/api/agente/` talk to OpenRouter through the Vercel AI SDK; they never write to the DB. The browser performs every write through one shared actions module after the user confirms.

**Tech Stack:** Next.js 16.3 App Router, React 19.2, TS 5, Supabase JS 2, Vitest + PGlite, new: `ai@^7`, `@ai-sdk/react@^4`, `@openrouter/ai-sdk-provider@^3.1`, `zod@^4`.

**Spec:** `docs/superpowers/specs/2026-10-28-agente-ia-design.md` (read it whole, including "Builder's calls").

## Global Constraints

- UI copy Spanish (Spain); code, comments, identifiers English; no emoji.
- Reuse existing classes/components (`Modal`, `CloseButton`, `FormField`, `RequiredMark`, `EmptyState`, `DeleteConfirmDialog`, `crm-*`, `filter-chip`, `rrhh-tabs`, `btn*`, `search-field`, `notice`, `form-error`); new CSS only when nothing fits, with existing variables.
- Next 16: read the relevant guide in `node_modules/next/dist/docs/` before writing route handlers or using routing APIs.
- AI SDK 7: read the installed docs (`node_modules/ai/` README/docs, `node_modules/@openrouter/ai-sdk-provider/` README) and use the current, non-deprecated APIs for structured output, streaming chat, tools and client-side tool results. Do not code from memory of older versions.
- Env: `OPENROUTER_API_KEY` (required, server only), `OPENROUTER_MODEL` (optional, default `nvidia/nemotron-3.5-super-vl:free`). Never read or write `.env*`; never print keys.
- IVA options exactly 21, 10, 4, 0. Default 21.
- Photo bucket `facturas-fotos`, public read, 10 MB, `image/png`, `image/jpeg`, `image/webp`; path `<factura id>/<timestamp>.<ext>`.
- Route handlers set `maxDuration = 60` and return 401 without a valid Supabase access token.
- Error copy: rate limit -> `El agente ha alcanzado el límite diario gratuito. Inténtalo mañana.`; missing key -> `Falta configurar OPENROUTER_API_KEY.`; duplicate number -> `Ya existe una factura con el número <numero>.`
- `npm test`, `npx tsc --noEmit`, no new lint errors in touched files (12 pre-existing set-state-in-effect errors are out of scope). Tests never call OpenRouter.
- No git commits or branches (user decision). Each task ends by reporting changed files.

## Review Focus

1. A photo invoice whose number already exists (F- series or another photo) must show the duplicate message on the field, not a generic error — Task 1 test `duplicate photo number raises factura_numero_duplicado` + Task 2 `invoiceErrorMessage` test.
2. A photo invoice must never break sale logic: a sale's "Sin facturar" ignores photo invoices and the F- counter ignores photo numbers like `F-2026-ABC` — Task 1 test `counter ignores non-numeric F numbers`, Task 2 test `buildSales ignores photo invoices`.
3. An AI result with garbage values (negative base, IVA 7, date "31/02/2026", total as string "1.234,56") must be normalised or left empty, never crash the form — Task 2 tests for `normalizeExtraction`.
4. A model/network failure or 429 from OpenRouter must surface the Spanish message, and the photo dialog must stay usable to fill the form by hand — Task 3 test `mapAgentError` + Task 4 manual path "Rellenar a mano".
5. Confirming a chat proposal that the DB rejects (e.g. issued invoice blocks a change) must show the DB message in the card and leave data unchanged — Task 6 uses `invoiceErrorMessage`.

### Task 2: Domain logic

**Files:**

**Interfaces:**
- Produces in `facturas.ts`: `Invoice` gains `origen: "venta" | "foto"`, `foto_path: string | null`, `oportunidad_id: string | null`; `IVA_OPTIONS = [21, 10, 4, 0] as const`; `type IvaPct = typeof IVA_OPTIONS[number]`; `invoiceErrorMessage(error: { message?: string } | null): string | null` — handles `factura_numero_duplicado:` (spec copy) and delegates `factura_emitida:` to `invoiceBlockMessage`.
- Produces in `invoiceExtraction.ts`:
  - `type InvoiceExtraction = { cliente_nombre: string | null; cliente_nif: string | null; numero: string | null; fecha_emision: string | null; fecha_vencimiento: string | null; base: number | null; iva_pct: number | null; total: number | null }`
  - `invoiceExtractionSchema` (zod object matching that type, every field nullable) — used by the route in Task 3.
  - `normalizeExtraction(raw: unknown): InvoiceExtraction` — dates to `YYYY-MM-DD` (accepts `dd/mm/yyyy`, `yyyy-mm-dd`; invalid → null), numbers from `1.234,56`/`1234.56` strings, negative → null, `iva_pct` not in `IVA_OPTIONS` → null, strings trimmed (empty → null).
  - `normalizeNif(nif: string | null): string | null` (uppercase, strip spaces, dots and dashes).
  - `matchClients(extraction: Pick<InvoiceExtraction,"cliente_nombre"|"cliente_nif">, companies: { id: string; nombre: string; nif: string | null }[]): { id: string; nombre: string; nif: string | null; exactNif: boolean }[]` — exact NIF first, then name contains either way, case- and accent-insensitive (`normalize("NFD")`), max 5.
  - `prefillAmounts(extraction): { base: number | null; iva_pct: IvaPct }` — base read, else `round2(total / (1 + iva/100))`, iva default 21.
  - `totalMismatch(base: number, iva: number, total: number | null): boolean` — true if `|invoiceTotal - total| > 0.05`.
- Produces in `invoiceActions.ts` (each returns `Promise<{ error: string | null; numero?: string | null }>` with the Spanish message via `invoiceErrorMessage(error) ?? <existing fallback>`): `issueDraft(invoice: Invoice, precio: number, today: Date)`, `markPaid(id: string)`, `cancelInvoice(id: string)`, `deleteDraft(id: string)`, `createDraftFromSale(sale: Sale, dates: { fecha_emision: string; fecha_vencimiento: string }, iva_pct: IvaPct)`, `createPhotoInvoice(input: { id: string; empresa_id: string; numero: string; fecha_emision: string; fecha_vencimiento: string; base: number; iva_pct: IvaPct; pagada: boolean; foto_path: string })`. Moving existing writes here must not change their behaviour (same guards `.eq("estado", ...)`, same `.select().single()`).

- [ ] **Step 1: Failing tests:** `normalizeExtraction` (each garbage case from Review Focus 3 → expected value), `normalizeNif("b-1234 567.8")==="B12345678"`, `matchClients` (exact NIF first and flagged; "clinica vega" matches "Clínica Vega SL"; no match → []), `prefillAmounts({total:121,iva_pct:21})` → base 100, `totalMismatch(100,21,121.04)===false`, `totalMismatch(100,21,125)===true`, `invoiceErrorMessage({message:"factura_numero_duplicado:2026/045"})` → `Ya existe una factura con el número 2026/045.`, `buildSales ignores photo invoices` (photo invoice with `oportunidad_id null` does not attach to any sale), `mapFacturaRow` maps `origen`/`foto_path`.
